## 页 2 · 背景与目标

**要点**

- **问题**:Agent 能力(会话、路由、进程编排、渠道)原本耦合在 localclaw 单体应用里,无法被 localcoding / teamai 等产品线复用。
- **目标**:抽取为独立 SDK,做到——
  - 框架无关:任意 Node 环境可用,不强绑 NestJS
  - 接口稳定:对外契约清晰,可按 semver 演进
  - 质量可信:有测试、有门禁、有准入材料,接入方放心
- **交付物**:4 个 npm 包 + 接口护栏 + 质量门禁 + 完整文档体系。

> 备注:强调从「单体内部模块」到「可对外发布的产品级 SDK」的转变。

## 页 3 · 总体思路

**要点(三条主线)**

1. **架构抽取** —— 按职责拆分为分层、单向依赖的包家族;纯类型与重依赖隔离。

**一句话**:架构定骨架,接口立契约,质量给信心。

## 页 4 · 架构总览:四包家族

**可视化建议**:依赖方向向下的分层图。

```
       @lenovo/agent-sdk-channel   (IM 渠道: 飞书/微信/钉钉)
              │           │
              ▼           │
       @lenovo/agent-sdk  │          (核心能力底座)
         │      │      │  │
         ▼      ▼      ▼  ▼
@lenovo/agent-protocol   @lenovo/claude-cli
   (纯类型 · 零依赖)       (CLI 产物 · 自包含)
```

**关键设计原则**
- 依赖**单向无环**:上层依赖下层,反之不行
- **纯类型独立**:protocol 零运行时依赖,前端安全引用
- **CLI 产物不外泄**:SDK spawn 它,接入方不直接碰
- **渠道可选**:不接 IM 的产品不承担 golembot 依赖

> 备注:拆包硬约束——前端要类型但不能拉 better-sqlite3;渠道能力较重要解耦。

## 页 5 · 包职责与依赖

| 包 | 职责 | 运行时依赖 | 装它的场景 |
| --- | --- | --- | --- |
| `agent-protocol` | 共享协议与领域类型 | 无 | 前端取类型 |
| `claude-cli` | 含 SmartHybrid 补丁的 CLI 产物 | 无(自包含) | 由 SDK spawn |
| `agent-sdk` | 核心底座(会话/路由/Runner/工作区/定时/WS) | protocol+cli+NestJS/sqlite3 | **主入口** |
| `agent-sdk-channel` | IM 渠道(飞书/企微/钉钉) | sdk+golembot | 接 IM 时 |

**数据**:核心包源码 ~7800 行 / 45 文件;协议包纯类型零依赖。

> 备注:接入方通常只需 `pnpm add @lenovo/agent-sdk`,其余自动拉取。

## 页 6 · 两种接入入口

| 入口 | 场景 | 代码量 |
| --- | --- | --- |
| `createAgent()` | 框架无关,任意 Node 环境,异步消息流 | **3 行** |
| `AgentModule.forRoot({ db })` | NestJS 宿主一站式装配 | **1 行** |

**createAgent 示例(极简)**:
```ts
const agent = await createAgent({ dbPath: "./data.db" });
for await (const msg of agent.run({ prompt: "写个贪吃蛇" })) {
  console.log(msg);
}
await agent.dispose();
```

> 备注:两入口共享全部底层实现,只是 DI 封装层级不同。NestJS 是实现细节,不泄漏到签名。

## 页 8 · 稳定性分层

```
┌────────────────────────────────────────────────┐
│  @public 公共面  (对外承诺,遵循 semver)          │
│  createAgent / AgentModule / 各 Service          │
│  注入令牌 / 类型 / 配置函数                        │
├────────────────────────────────────────────────┤
│  @internal 实现管线  (随时可改,不计入版本)        │
│  RunnerSpawnService / SmartHybridService         │
│  OllamaService / EndpointRegistryService         │
│  ENV_DIRECT_ID / modelTier / ENDPOINT_PRESETS    │
└────────────────────────────────────────────────┘
```

- 每个包 `src/index.ts` 是唯一公共出口
- 导出分两段,TSDoc `@internal` 标注
- 接入方只依赖 @public → 升级安全

> 备注:本次建设中修了一个真实 bug——`@internal` 写在 re-export 处不生效,api-extractor 按符号**声明处**标签判定,4 个端点符号曾意外泄漏为 @public,已在声明处修正。

## 页 9 · 接口治理:API 护栏

**机制**:API Extractor 从类型声明抽取公共面 → 生成可 diff 的快照 `etc/*.api.md`。

```
改 index.ts 导出  →  pnpm api:check  →  diff 符合预期?
                          │(不符即 CI 红)        │
                          ▼                      ▼ 是
                     阻断合并            pnpm api:update 更新基线
```

**价值**
- 公共面任何变动「显式可见」,杜绝无声破坏
- `etc/*.api.md` 就是交付给接入方的**接口契约书**,可逐版 diff
- 覆盖 protocol / sdk / channel 三包

> 备注:命令 `api:check`(校验)/`api:update`(更新基线)。这是「接口立契约」的核心抓手。

---

## 页 10 · 版本与发布:changesets

**机制**:每次接口改动附带一个 changeset 文件,声明版本级别与迁移说明 → 发版时统一消费、bump 版本、生成 CHANGELOG。

| 改动类型 | 版本级别 |
| --- | --- |
| 新增 @public 导出 | minor |
| 修改/删除已发布 @public(破坏下游) | **major** |
| 纯文档/内部重构 | patch 或无需 |

**配置要点**:私仓 restricted 发布;private 包自动跳过;baseBranch=main。

> 备注:配套脚本 `changeset` / `version-packages` / `release`。CHANGELOG + semver 承诺是接入方信心来源之一。

---

## 页 11 · 质量保障体系:四道门禁

**任一不过,CI 阻断合并**:

| 门禁 | 命令 | 作用 |
| --- | --- | --- |
| 类型检查 | `pnpm typecheck` | 三包 tsc --noEmit,类型零容忍 |
| 接口护栏 | `pnpm api:check` | 公共面无意外漂移 |
| 单元测试 | `pnpm test` | 全部用例通过 |
| 覆盖率 | `pnpm test:coverage` | 不低于阈值(ratchet 只升不降) |

**可视化建议**:四个并排「关卡/闸门」图标。

> 备注:门禁是「质量给信心」的制度保障——不靠自觉,靠 CI 强制。

## 页 13 · CI/CD 门禁

**改造前**:CI 只在单一分支构建安装包,**不跑任何测试**。
**改造后**:新增 `verify` 阶段,所有分支/MR 触发。

```
stages: [verify, build]

verify:  typecheck → api:check → test:coverage
         ↓ 产出 cobertura 报告 + MR 覆盖率徽章
build:   (原有) 构建安装包
```

**价值**:坏改动在合并前被挡住;MR 自动显示覆盖率徽章与行级标注。

> 备注:从「没有质量门禁」到「四道强制门禁」,是工程化的关键跃迁。

## 页 15 · 接入方准入材料

**给接入方的「可验证证据」,而非口头承诺**:

1. **接口契约书** — `etc/*.api.md` 完整公共面快照,可逐版 diff
2. **运行时契约测试** — 断言所有对外入口确实存在
3. **端到端冒烟** — 证明「几行代码跑通对话」可用
4. **CHANGELOG + semver** — 每版变更与破坏性标注
5. **覆盖率报告** — CI 产出 cobertura + 徽章
6. **稳定性分层声明** — 只依赖 @public 即升级安全
7. **兼容性矩阵 + 五分钟自测** — Node/DB/OS 要求 + 最小验证代码

> 备注:这是「让大家放心」的核心交付——把信任建立在可核验的材料上。
